# Spring

[전체 목차](../README.md)

Spring MVC(서블릿 스택)에서 요청 하나가 들어와 응답이 나가기까지를, 그 요청을 맡은 스레드 하나의 여정으로 따라간다. 2026-11-24 발표 "요청 하나, 스레드 하나"를 준비하며 공부했고, 예시는 `GET /api/health`와 주문 요청(`POST /api/orders/{shopId}`)이다. 기준은 Spring Boot 3.x(Spring Framework 6, 내장 톰캣)이며, Nest와 비교는 각 노트 안에 짧게 둔다.

Part 2는 그 길의 부품인 빈이 서버가 켜질 때 어떻게 만들어지고, 어떻게 읽히고, 어떻게 감싸지는지를 공부한다. 2026-12-01 발표를 함께 준비한다.

## 전체 흐름

요청 하나는 아래 11단계를 지난다. 1단계부터 10단계까지는 톰캣의 작업 스레드 하나(예: `http-nio-8080-exec-3`)가 혼자 처리한다.

| 단계 | 이름 | 하는 일 | 노트 |
| --- | --- | --- | --- |
| 0 | 연결 | nginx가 TLS를 풀고 톰캣에 넘긴다 | 1 |
| 1 | 톰캣 | 요청을 작업 스레드 하나에게 맡긴다 | 1 |
| 2 | 필터 | 서블릿 필터가 요청을 걸러낸다 | 2 |
| 3 | 정문 | DispatcherServlet에 들어온다 | 3 |
| 4 | 길 찾기 | HandlerMapping이 핸들러와 인터셉터를 찾는다 | 3 |
| 5 | 인터셉터 | 실행 앞뒤를 감싼다 | 3 |
| 6 | 입력 변환 | ArgumentResolver가 요청 값을 파라미터로 꺼내 넣는다 | 3 |
| 7 | 서비스·DB | 우리가 짜는 비즈니스 로직, `@Transactional`, JDBC | 4 |
| 8 | 출력 변환 | 메시지 컨버터가 리턴값을 JSON으로 바꾼다 | 3 |
| 9 | 예외 | 예외가 나면 어디서 났느냐에 따라 잡는 곳이 갈린다 | 5 |
| 10 | 복귀 | 들어온 길을 거꾸로 나가고, 스레드는 풀로 돌아간다 | 5 |

이 길에서 우리가 직접 짜는 건 사실상 7단계뿐이다. 나머지는 Spring과 톰캣이 하고, 그 설정은 Spring Boot가 꾸려 준다.

## 읽는 순서

1. [요청은 어떻게 스레드 하나에게 갈까?](request-to-thread.md)
   - nginx의 TLS, 톰캣의 Acceptor·Poller·작업 스레드, 연결이 아니라 요청 하나에 스레드 하나, 스레드 풀 200개를 정리한다.
2. [필터는 무엇을 걸러내고, Spring은 어디서부터일까?](filter.md)
   - 서블릿 표준 필터, doFilter의 앞뒤, chain.doFilter로 걸러내기(401·429), Spring Security 필터, @RestControllerAdvice의 경계선을 정리한다.
3. [DispatcherServlet은 요청을 어떻게 내 메서드까지 보낼까?](dispatcher-servlet.md)
   - HandlerMapping 주소 표, HandlerExecutionChain, 인터셉터 세 시점과 등록 방식, HandlerAdapter, ArgumentResolver, 역직렬화·직렬화를 정리한다.
4. [@Transactional은 DB 연결을 어떻게 붙잡고 있을까?](transaction-and-db.md)
   - 프록시와 트랜잭션 매니저, ThreadLocal, HikariCP, JDBC와 드라이버, 외부 API가 느릴 때 스레드 200개·연결 10개가 바닥나는 이유와 대비책을 정리한다.
5. [응답과 예외는 어떤 길로 나갈까?](response-and-exception.md)
   - 응답이 거꾸로 나가는 이유(호출 스택), 예외는 DispatcherServlet 안이냐 밖이냐, 필터 예외를 처리하는 네 가지를 정리한다.
6. [빈은 어떻게 만들어질까?](bean-creation.md)
   - 찾기(컴포넌트 스캔) → 적기(빈 정의) → 만들기(생성자 주입) → 마무리(후처리)의 네 칸, 리플렉션을 쓰는 곳과 Metaspace·힙, 순환 참조, 주입 타이밍, 후처리기와 프록시를 정리한다.

## 공부 계획

주제를 통과하면 체크하고, 노트를 위 "읽는 순서"에 올린다.

**Part 1. 요청 하나가 지나는 길**

- [x] 1. 요청은 어떻게 스레드 하나에게 갈까?
- [x] 2. 필터는 무엇을 걸러내고, Spring은 어디서부터일까?
- [x] 3. DispatcherServlet은 요청을 어떻게 내 메서드까지 보낼까?
- [x] 4. @Transactional은 DB 연결을 어떻게 붙잡고 있을까?
- [x] 5. 응답과 예외는 어떤 길로 나갈까?

**Part 2. 그 길을 가능하게 하는 것** (다음 공부: 7번)

- [x] 6. 빈은 어떻게 만들어질까? — 컴포넌트 스캔, 빈 정의, 생성과 의존성 주입, 생명주기
- [ ] 7. 리플렉션은 어떻게 어노테이션을 읽고 메서드를 부를까?
- [ ] 8. AOP 프록시는 어떻게 `@Transactional`을 감쌀까? — JDK 동적 프록시와 CGLIB, 자기 호출 문제

Part 1 노트의 남은 질문 중 Part 2에서 답할 것: 빈 생성 순서와 리플렉션 비용([3장](dispatcher-servlet.md)) → 6·7번, JDK 동적 프록시와 CGLIB([4장](transaction-and-db.md)) → 8번.
