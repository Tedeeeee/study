# study

궁금했던 질문에서 출발해 개념의 흐름을 설명하고, 헷갈렸던 점과 직접 확인한 예제를 함께 남깁니다. 공부하면서 이해가 달라지면 문서도 계속 수정합니다.

## 문서를 묶는 기준

관련 개념을 하나의 큰 주제로 묶고, 세부 개념은 문서 안의 소제목으로 정리합니다.

| 큰 주제의 예 | 문서 안에서 함께 설명할 개념 |
| --- | --- |
| 운영체제 기초 | 프로그램, 프로세스, 스레드, 실행 권한, 장치 파일 |
| 메모리 관리 | 메모리 계층, 가상 메모리, 프로세스의 메모리 공간 |
| 파일과 I/O | 파일 열기와 읽기, FD, Page Cache, 대기와 완료 |
| 동시성 | 작업의 교차 실행, 공유 데이터, 경쟁 상태, 동기화 |

문서의 범위가 커지거나 독립적으로 설명할 흐름이 생기면 그때 분리합니다. 같은 개념을 다른 강의에서 다시 배우면 기존 문서에 설명과 출처를 보완합니다.

## 저장소 구조

```text
study/
├── README.md
├── operating-system/   # 운영체제
├── network/            # 네트워크
├── database/           # 데이터베이스
├── java/               # Java
├── docker/             # Docker
├── observability/      # 모니터링과 옵저버빌리티
└── templates/          # 학습 문서 양식
```

각 분야에는 목차 역할을 하는 `README.md`와 학습 문서를 둡니다. 실습 코드가 생기면 해당 분야의 `examples/` 아래에 추가하고, 관련 문서에서 실행 방법과 결과를 연결합니다.

## 공부하고 기록하는 흐름

1. 질문을 풀어가며 한 번에 개념 하나씩 공부합니다.
2. 이해한 내용을 내 말로 설명하고, 필요한 부분은 공식 문서나 실습으로 확인합니다.
3. 관련 개념들이 연결되면 큰 주제의 문서에 모아 정리하고 분야별 목차에 추가합니다.

정리에는 **시작한 질문, 이해한 흐름, 헷갈렸던 점, 예제와 결과, 남은 질문, 참고 자료**를 담습니다. 실제 실행한 예제와 설명용 코드를 구분하고, 강의명·강사명과 문서 링크를 남깁니다.

새 문서는 [학습 문서 양식](templates/study-note.md)을 복사해서 시작합니다.
