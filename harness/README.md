# Harness

[전체 목차](../README.md)

AI 에이전트의 하네스를 공부한다. 하네스는 에이전트에서 모델을 뺀 나머지 전부를 말한다. 모델에게 무엇을 보여 주고, 무엇을 할 수 있게 하고, 어떻게 바로잡고, 어떻게 고쳐 가는지를 차례로 본다.

각 주제는 하네스를 쓰는 쪽과 만드는 쪽 양쪽에서 본다. 쓰는 쪽은 Claude Code 2.1.x를 기준으로 하고 Codex(codex-cli 0.16x)와 다른 점을 짧게 둔다. 만드는 쪽은 오픈소스 하네스의 소스로 실제 구현을 확인한다. 최소 루프는 mini-swe-agent(Python, MIT), 코딩 하네스는 Codex CLI, 다 갖춘 하네스는 Hermes Agent(Nous Research, MIT)를 본다. 목표는 어느 하나를 똑같이 만드는 것이 아니라, 하네스 전체가 어떤 부품으로 이뤄지고 어떻게 맞물리는지 이해하는 것이다. 버전에 따라 달라지는 내용은 확인한 버전과 함께 적는다.

## 읽는 순서

1. [모델은 글만 만드는데, 어떻게 파일을 고칠까?](agent-loop.md)
   - 요청서(`tool_use`)와 결과(`tool_result`), 도구 목록, 에이전트 루프, 다시 도는 조건과 `stop_reason`, 에이전트 = 모델 + 하네스, 문서와 코드의 차이를 정리한다.
2. ["하네스"는 정확히 어디까지일까?](what-is-harness.md)
   - 정의가 갈리는 이유, 내장 하네스와 사용자 하네스, mini-swe-agent의 최소 부품과 끝내는 방식, Hermes에서 더 붙는 부품, 하네스만 바꿔도 달라지는 결과, 컨텍스트 엔지니어링과의 관계를 정리한다.
3. [AI는 내 규칙을 어떻게 "기억"할까?](instructions-and-memory.md)
   - 매번 다시 보내는 대화와 프롬프트 캐시, 첫 요청에 깔리는 것, 시스템 프롬프트·CLAUDE.md·메모리의 차이, 도구와 훅, "강제가 아니라 컨텍스트", 막는 층과 샌드박스를 정리한다.
4. [컨텍스트가 차면 무슨 일이 생길까?](when-context-fills.md)
   - 꽉 차기 전부터 생기는 문제, 압축과 남는 것, 필요할 때만 불러오기(스킬), 도구 결과 짧게 받기, 하위 에이전트, 설명서 말고 지도를 정리한다.
5. [도구와 권한은 어떻게 설계할까?](tools-and-permissions.md)
   - 모델을 위한 API(ACI)와 poka-yoke, 결과와 오류 메시지 설계, 스크립트·셸·bash, bash 하나와 전용 도구, 되돌릴 수 있는지로 나누는 권한과 샌드박스를 정리한다.
6. [무엇을 글로 안내하고, 무엇을 코드로 막을까?](guides-and-sensors.md)
   - 가이드와 센서, 계산형과 추론형, AI 리뷰를 믿을 만하게 만드는 법, 센서를 만드는 법과 거는 자리, 규칙을 둘 자리를 정하는 질문 세 개를 정리한다.
7. [루프의 어디에 코드를 끼울 수 있을까?](hooks.md)
   - 도구·시점·훅·훅 스크립트의 구분, 훅으로 할 수 있는 네 가지와 대표 시점, 설정과 matcher, 표준 입출력과 종료 코드, 훅을 적는 곳과 Codex 비교, 실습, 에이전트와 워크플로를 정리한다.
8. [AI가 검사를 통과해야만 끝나게 하려면?](completion-gate.md)
   - 완료 게이트(Stop 시점 + 검사 훅), 무한 루프 막기, "끝"의 정의와 작업별 체크리스트, 평가자 분리와 비용·시간, 게이트가 보장하는 범위를 정리한다.
9. [몇 시간짜리 일은 어떻게 이어 갈까?](long-running-work.md)
   - 창 하나로 긴 일을 할 때의 두 가지 실패, 교대 세션(준비 담당과 작업 담당, 바깥 루프), 인수인계 파일 네 가지, 작업 담당 창의 출근·점검·일·퇴근, 압축과 리셋과 컨텍스트 불안을 정리한다.

## 공부 계획

주제를 통과하면 체크하고, 노트를 위 "읽는 순서"에 올린다.

**Part 1. 하네스란 무엇인가**

- [x] 1. 모델은 글만 만드는데, 어떻게 파일을 고칠까? — 도구 호출과 결과, 에이전트 루프, 멈추는 이유(stop_reason), 에이전트 = 모델 + 하네스
- [x] 2. "하네스"는 정확히 어디까지일까? — 글마다 정의가 갈리는 이유, 내장 하네스와 사용자 하네스, 컨텍스트 엔지니어링과의 관계, 하네스만 바꿔서 결과가 달라진 사례

**Part 2. 모델에게 무엇을 보여 줄까 (컨텍스트)**

- [x] 3. AI는 내 규칙을 어떻게 "기억"할까? — 상태 없는 API, 매번 다시 보내는 대화, 지시 파일(CLAUDE.md·AGENTS.md)이 들어가는 자리, "강제가 아니라 컨텍스트"
- [x] 4. 컨텍스트가 차면 무슨 일이 생길까? — 길어질수록 흐려지는 컨텍스트, 압축 뒤 남는 것과 사라지는 것, 필요할 때만 불러오기(스킬), 하위 에이전트로 나누기, "설명서가 아니라 지도"

**Part 3. 무엇을 할 수 있게 할까 (도구와 환경)**

- [x] 5. 도구와 권한은 어떻게 설계할까? — 적고 분명한 도구, 고칠 방법을 알려 주는 오류 메시지, 권한 규칙과 샌드박스, 에이전트가 볼 수 있는 것만 존재한다

**Part 4. 어떻게 바로잡을까 (가이드와 센서)**

- [x] 6. 무엇을 글로 안내하고, 무엇을 코드로 막을까? — 가이드와 센서, 계산형 검사와 추론형 검사, 성공은 조용히 실패는 자세히
- [x] 7. 루프의 어디에 코드를 끼울 수 있을까? — 훅이 걸리는 순간들, 막으면서 이유를 돌려주는 방법, Claude Code와 Codex 비교
- [x] 8. AI가 검사를 통과해야만 끝나게 하려면? — 완료 게이트, 무한 루프 막기, "끝"의 정의, 자기 평가 편향과 평가자 분리

**Part 5. 큰 일을 어떻게 맡길까**

- [x] 9. 몇 시간짜리 일은 어떻게 이어 갈까? — 일찍 "완료"를 선언하는 문제, 진행 파일과 git으로 상태 넘기기, 압축과 컨텍스트 리셋
- [ ] 10. 여러 에이전트로 나누면 무엇이 좋아지고 무엇이 비싸질까? — 지휘자와 작업자, 병렬 실행, 토큰 비용

**Part 6. 하네스를 어떻게 고쳐 갈까**

- [ ] 11. 하네스가 잘 돌고 있는지 어떻게 알까? — 세션 기록과 OTel, 에이전트 평가, 실패 사례에서 시작하기
- [ ] 12. 하네스는 언제 고치고 언제 걷어낼까? — 실수 하나가 규칙 하나가 되는 과정, 모델 한계에 대한 가정과 그 수명

**Part 7. 직접 만들기**

- [ ] 13. 작은 하네스를 바닥부터 만들어 보기 — 모델 API를 부르는 루프부터 도구, 지시 파일, 스킬, 완료 게이트, 기록까지 핵심만 직접 만들어 돌려 본다

## 기록 기준

- 각 문서는 시작한 질문, 이해한 내용, 헷갈렸던 점, 예제와 확인 결과, 남은 질문, 참고 자료를 연결한다.
- 헷갈렸던 점에는 공부하며 실제로 헷갈린 것과 확인 문제·내 답을 남긴다.
- 설명용 예제와 실제로 실행한 결과를 구분한다. 실행했다면 도구 버전과 실행 환경을 적는다.
- 개념은 공개된 1차 자료(각 도구의 공식 문서, 하네스 엔지니어링 글)를 기준으로 하고, 참고 자료에 출처를 적는다.
- 만드는 쪽 설명은 참고한 오픈소스 하네스의 파일 경로와 확인한 버전(커밋)을 함께 적는다. 공식으로 공개되지 않은 소스(유출본 등)는 쓰지 않는다.
- 회사 프로젝트에서 본 사례는 이름과 내용을 일반화해서 쓴다.
