# Redis

[전체 목차](../README.md)

Redis의 동작 원리와 사용법을 서버 한 대 → 애플리케이션에서 쓰기 → 운영 순서로 공부한다. 기준 버전은 Redis 8.x이며, 이전 버전과 달라진 내용은 바뀐 버전과 함께 적는다. 실습은 Docker로 띄운 Redis와 `redis-cli`로 한다.

## 읽는 순서

1. [Redis는 왜 빠를까?](why-redis-fast.md)
   - 메모리와 MySQL 버퍼 풀, 단순한 처리 과정, 싱글 스레드와 동시성, epoll과 이벤트 루프, RTT와 파이프라이닝을 정리한다.
2. [자료구조는 언제 무엇을 쓸까?](data-structures.md)
   - String, Hash, List, Set, Sorted Set의 쓰임과 내부 구조, 만료시간, 자료구조 고르는 법, 시간복잡도와 큰 키 문제를 정리한다.

## 공부 계획

주제를 통과하면 체크하고, 노트를 위 "읽는 순서"에 올린다.

**Part 1. 서버 한 대로 이해하기**

- [x] 1. Redis는 왜 빠를까? — 메모리 저장, 단순한 처리 과정, 싱글 스레드와 이벤트 루프, 파이프라이닝
- [x] 2. 자료구조는 언제 무엇을 쓸까? — String, Hash, List, Set, Sorted Set, 시간복잡도, 큰 키 문제
- [ ] 3. 키는 언제 사라질까? — TTL 삭제 방식, `maxmemory`와 축출 정책(LRU, LFU)

**Part 2. 애플리케이션에서 쓰기**

- [ ] 4. 캐시는 어떻게 붙일까? — Cache-aside, Write-through, DB와 캐시의 정합성, 캐시 스탬피드
- [ ] 5. 여러 요청이 동시에 오면? — 원자성, `MULTI/EXEC`, Lua 스크립트, 분산 락, 요청 수 제한
- [ ] 6. 메시지 전달에도 쓸 수 있을까? — Pub/Sub와 Streams, Kafka와 비교

**Part 3. 운영하기**

- [ ] 7. 꺼지면 데이터는 어떻게 될까? — RDB와 AOF, fork와 Copy-on-Write
- [ ] 8. 서버가 죽으면? — 복제와 Sentinel
- [ ] 9. 데이터가 서버 한 대를 넘으면? — Cluster와 해시 슬롯, 리샤딩, 멀티 키 명령의 제약
